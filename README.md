# 我的电视 · my-tv

**当前版本：v1.0.0**

我的电视是一款面向 Android 电视、电视盒子和手机的直播播放器。本项目基于 lizongying/my-tv 改造，通过 M3U 订阅加载频道，通过 XMLTV 节目单显示节目信息，将同一频道的多条来源聚合到一个频道入口。

适合将自建 IPTV 服务提供的直播列表统一呈现在电视和手机上。应用负责播放和换源，频道内容及直播地址由订阅服务提供。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 直播播放 | 使用 ExoPlayer 播放直播，支持 HTTP/HTTPS HLS 等已接入的媒体格式 |
| 频道聚合 | 根据规范化频道名称合并来源、去重地址，保留订阅中的分类入口 |
| 央视频优先 | 频道包含可识别的央视频来源时，选台优先使用该来源 |
| 历史画质排序 | 同一来源优先级内，优先历史分辨率较高的源；分辨率相同时优先历史首帧耗时较短的源 |
| 手动选源 | 底部面板显示来源名称、实时或历史分辨率，以及播放失败提示 |
| 故障换源 | 当前源明确失败或持续卡顿时，停止旧播放，再串行尝试同频道备用源 |
| 失败冷却 | 限制每轮尝试次数，失败源暂时冷却；无可用源时停止并提示 |
| 频道菜单 | 浏览分类和频道时保留直播画面，打开菜单定位到当前播放频道 |
| 电视与手机操作 | 支持遥控器方向键、确认键、数字选台，以及手机触摸按钮 |
| 节目单 | 解析 XMLTV，按频道标识或名称匹配节目信息 |
| 自动刷新与缓存 | 定期更新订阅和 EPG，网络异常时保留已有列表和节目单 |
| 常用设置 | 换台方向反转、换台时显示频道号、开机自启 |

## 选源与故障处理

### 选台规则

1. 排除正在失败冷却期内的来源。
2. 优先选择央视频来源；识别依赖订阅元数据及地址信息，无法从不透明的中转地址保证识别上游。
3. 同一来源优先级内，按照历史实际播放分辨率、首帧耗时排序。
4. 没有播放记录时，保留订阅中的默认顺序。

播放器按设备解码能力选择媒体轨道。历史画质来自该设备上的实际播放，不代表所有未播放来源中的最高画质。

### 不做后台直播探测

- 不创建隐藏播放器检测其他来源，不批量测速，也不抓取直播预览图。
- 仅从当前实际播放记录分辨率、首帧耗时和播放失败结果。
- 播放过程中不主动切换到更高清的来源，历史记录用于下次选台。
- 手动点击某个来源后才请求该来源，成功后更新记录。
- 订阅和 EPG 刷新仅下载列表与节目单，不逐条请求直播地址。

选源面板中的“历史播放”表示曾经成功播放时的画质，不表示地址当前已验证有效。“实时”表示当前播放画质，未知来源显示“尚未播放，分辨率未知”。

### 自动换源

- 播放错误、直播意外结束、持续卡顿等情况会触发同频道换源。
- 每轮最多尝试 3 条来源，重试之间递增等待；先停止旧请求，再请求备用源。
- 失败来源自动冷却 10 分钟，手动选源可以立即重试。
- 来源耗尽或达到尝试上限后停止并提示，不自动遍历其他频道。

这些策略减少额外直播请求，来源仍可能受服务端权限、并发数、限流和地址有效期影响。

## 操作说明

### 电视遥控器

| 场景 | 按键 | 操作 |
| --- | --- | --- |
| 直播画面 | 左方向键 | 打开分类和频道菜单 |
| 频道菜单 | 方向键 | 移动分类或频道焦点，浏览时菜单保持显示 |
| 频道菜单 | 确认键 / 中间键 | 播放选中频道并关闭菜单 |
| 直播画面 | 确认键 / 中间键 | 打开底部选源面板 |
| 选源面板 | 方向键 + 确认键 | 选择并播放来源 |
| 直播画面 | 上 / 下或频道加减键 | 换台，方向可在设置中反转 |
| 直播画面 | 数字键 | 输入频道号选台 |
| 直播画面 | 右方向键或菜单键 | 打开设置 |
| 菜单或面板 | 返回键 | 关闭当前菜单或面板 |

### 手机触摸

- 点击右下角“频道”打开或关闭频道菜单。
- 点击分类和频道进行选择；触摸选台后保留菜单，便于连续浏览。
- 点击右下角“选源”打开底部面板，点击来源即可切换。
- 点击面板外区域或按返回键关闭选源面板。
- 应用采用横屏播放布局。

## 订阅与节目单

订阅与 EPG 地址由项目根目录的本地配置文件 `iptv.properties` 管理：

```sh
cp iptv.properties.example iptv.properties
```

将本地文件中的示例地址替换为自己的服务地址：

```properties
subscription.url=https://example.com/iptv/interface.m3u
epg.url=https://example.com/iptv/playback.xml
```

`subscription.url` 为 M3U 订阅，`epg.url` 为默认 XMLTV 节目单，两项均需填写有效的 HTTP/HTTPS 地址。订阅头声明了 `x-tvg-url` 时，优先使用声明的节目单地址。

`iptv.properties` 已加入 `.gitignore`，只保存在本地，不提交到 GitHub。仓库仅保留不含实际地址的 [配置示例](iptv.properties.example)。构建时将配置写入 APK，更换地址后需重新编译安装；当前没有应用内地址编辑界面。设备需要能访问配置的服务器。

配置缺失或地址格式错误时，构建会明确提示。GitHub Actions 构建会从仓库 Secrets `IPTV_SUBSCRIPTION_URL` 和 `IPTV_EPG_URL` 生成此文件，需先在仓库中设置这两项。地址会包含在生成的 APK 中，本地配置忽略规则不用于隐藏 APK 中的地址。

应用在前台运行时，订阅约每 30 分钟刷新，EPG 约每 15 分钟刷新，失败后约 5 分钟重试。刷新列表不会主动重启正在播放的直播，EPG 加载失败也不会阻止频道列表显示。

### M3U 示例

```m3u
#EXTM3U x-tvg-url="http://server/playback.xml"
#EXTINF:-1 tvg-id="cctv1" tvg-name="CCTV-1" group-title="央视" source-name="央视频",CCTV-1
http://server/live/cctv1-ysp.m3u8
#EXTINF:-1 tvg-id="cctv1" tvg-name="CCTV-1" group-title="央视" source-name="咪咕",CCTV-1
http://server/live/cctv1-migu.m3u8
```

这两条地址会聚合为一个频道，选源面板分别显示“央视频”和“咪咕”。建议使用一致的频道名称、准确的 `tvg-id` 和明确的 `source-name`，避免不同频道被误合并或来源无法识别。

## 安装

运行环境：Android 5.0（API 21）及以上，ARM 32 位或 ARM64 设备。电视与盒子支持遥控器操作，手机支持触摸操作。

可通过 U 盘、设备安装器或 ADB 安装已编译的 APK：

```sh
adb devices
adb -s <设备序列号> install -r app/build/outputs/apk/debug/app-debug.apk
```

`install -r` 用于覆盖安装并保留应用数据，要求新旧 APK 的包名和签名一致。

## 编译与验证

项目使用 Kotlin、AndroidX Leanback、Media3 ExoPlayer，并保留部分旧版 ExoPlayer 设备兼容逻辑。

准备 JDK 17、Android SDK 34、Build Tools 36.0.0，以及项目构建所需的 NDK 和 CMake（CMakeLists 要求至少 3.21.1）。配置 Android SDK 路径及上述 `iptv.properties` 后执行：

```sh
# 编译调试 APK
./gradlew :app:assembleDebug

# 执行单元测试
./gradlew :app:testDebugUnitTest

# 编译 release APK
./gradlew :app:assembleRelease
```

输出目录：

- Debug：`app/build/outputs/apk/debug/app-debug.apk`
- Release：`app/build/outputs/apk/release/`

当前本地构建的 release 也使用 debug 签名配置，正式分发应配置自己的签名。

### 版本管理

[version.json](version.json) 是 APK 版本信息的统一来源：

```json
{"version_code": 33619972, "version_name": "1.0.0"}
```

`version_name` 是用户可见版本，设置页显示为 `v1.0.0`；`version_code` 是 Android 内部升级编号。当前保留递增的内部编号，以便覆盖安装此前的调试版本。后续发布需同时更新可见版本并递增内部编号，构建不再根据 Git 标签自动生成版本。

## 当前限制

- 当前未接入 ExoPlayer RTSP 模块，不支持直接播放 `rtsp://` 地址。后台转为可播放的 HTTP/HLS 后，使用转换后的地址。
- 4K、H.265 等格式是否可播放取决于设备解码能力和直播本身，不保证所有电视都能播放。
- 不预先检测未播放的来源，因此无法保证第一次选台就是所有来源中的最高分辨率。
- 历史首帧耗时用于加载速度排序，不是带宽测速；短时卡顿记录用于当前播放监控，尚未持久化完整卡顿统计。
- 开机自启效果取决于系统是否允许应用接收启动广播及启动界面。
